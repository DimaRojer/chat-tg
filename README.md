# Telegram Chat — тестовое задание (Green API)

Простой веб-клиент для отправки и получения **текстовых** сообщений через [Green API](https://green-api.com).

> Задание просило реализовать интерфейс для мессенджера **MAX**. Реализация выполнена для **Telegram** (это допускается условиями задания в качестве альтернативы). Внешний вид ориентирован на прототип https://web.max.ru/.

## Стек

- React 19 + TypeScript
- React Router
- Vite
- SCSS

## Как это работает

1. Пользователь вводит `idInstance` и `apiTokenInstance` от своего инстанса Green API (страница `/auth`).
2. Данные сохраняются в `localStorage` браузера (учебный проект, без бэкенда).
3. Пользователь создаёт чат по номеру телефона собеседника.
4. Приложение резолвит настоящий Telegram `chatId` этого номера через метод [`CheckAccount`](https://green-api.com/telegram/docs/api/service/CheckAccount) и сохраняет его вместе с чатом.
5. Отправка сообщений — методом [`SendMessage`](https://green-api.com/v3/docs/api/sending/SendMessage/).
6. Получение сообщений — через периодический поллинг [`ReceiveNotification` / `DeleteNotification`](https://green-api.com/v3/docs/api/receiving/technology-http-api/) (технология Notification API, без вебхука на внешний сервер).

## Локальный запуск

```bash
npm install
npm run dev
```

Откройте `http://localhost:5173`, введите свои `idInstance` и `apiTokenInstance` на странице авторизации.

Сборка продакшн-бандла:

```bash
npm run build
npm run preview
```

## Важно про dev-прокси

В `vite.config.ts` настроен прокси `/green-api` → `https://api.green-api.com`, чтобы обойти CORS в режиме разработки (`npm run dev`).

**Этот прокси работает только через dev-сервер Vite.** Если разворачивать статическую сборку (`npm run build`) на обычном статическом хостинге (Vercel/Netlify без serverless-функций), запросы к `/green-api/*` не будут никуда проксироваться. Для продакшн-деплоя нужно либо:
- добавить serverless-функцию/rewrite на хостинге, проксирующую `/green-api/*` на `https://api.green-api.com`, либо
- ходить в Green API напрямую с полным `apiUrl`, если это разрешает CORS.

## Ограничения тарифа Green API

На бесплатном/пробном тарифе Green API ограничивает количество разных собеседников в месяц (`CORRESPONDENTS_QUOTE_EXCEEDED` в ответе `SendMessage`). Приложение показывает это как понятное сообщение прямо в чате, но само ограничение — на стороне Green API, обойти его на фронтенде нельзя.

## Что реализовано

- Авторизация по `idInstance` / `apiTokenInstance`
- Создание чата по номеру телефона (с защитой от дублей по номеру)
- Отправка и получение только текстовых сообщений
- Резолвинг реального Telegram `chatId` через `CheckAccount` (matching входящих сообщений идёт по `chatId`, а не по номеру телефона — это важно, т.к. Telegram-идентификатор Green API не совпадает с номером телефона)
- Отображение ошибок отправки (лимит тарифа, отсутствие Telegram-аккаунта и т.д.) прямо в интерфейсе чата
